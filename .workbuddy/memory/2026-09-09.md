## 用户反馈「手机上还是不能自动切换自如」→ 全面排查调度链路

### 真正的元凶：seed 用 Flow.first() 误判，示例数据从未写入
- `MainViewModel.seedExamplesIfNeeded` 原用 `r.observeProfiles().first()` 判断是否首次启动。
  Room 数据库首次打开时 Flow 首次发射时序不可靠，导致误判为「已有数据」→ 跳过创建。
- 后果：**模式表和时间段表全空** → `computeNextSwitch` 返回 null → 从来没有排过任何 alarm → 永不自动切换。
- 日志佐证（修复前）：`applyCurrent -> （无匹配模式）` + `scheduleNext -> 无切换点`，且无异常。
- **修复**：改用 suspend 直接查询 `r.getAllProfiles()`；并加「模式表为空就重建示例」自愈兜底；全流程加日志。
- 修复后日志：`seed 完成: 模式=3 时间段=2`、`applyCurrent -> 上班·静音震动`、`scheduleNext -> 09-09 18:01`。

### 其余调度健壮性修复
1. **冷启动/回前台从不重排**（致命）：`MainViewModel.init` 只 `refreshAll()` 从不 `scheduleNext()`。
   → 改为 `rescheduleAndApply()`；`MainActivity` 加 Lifecycle ON_RESUME → `viewModel.onResume()` 补排。
2. **准点率**：`setExactAndAllowWhileIdle` 在 Doze 下被节流推迟。
   → 有精确权限时改用 `AlarmManager.setAlarmClock`（闹钟级优先级，Doze 免疫；代价是状态栏显示闹钟图标，点击打开 App）。
3. **无兜底**：新增 15 分钟看门狗 alarm（`ACTION_APPLY_CURRENT`），幂等 applyCurrent+scheduleNext，任何一次切换被吞都能 15 分钟内补正。
4. **时间变更错位**：BootReceiver + Manifest 补 `TIME_SET` / `TIMEZONE_CHANGED` / `DATE_CHANGED`。
5. **可自查性**：状态页新增「自动切换诊断」卡（下次切换 / 上次应用 / 精确闹钟 / 电池优化）；设置页给精确闹钟和电池优化加状态徽章。
6. **同类崩溃隐患**：「忽略电池优化」按钮也是裸 `startActivity`（和之前勿扰权限崩溃同款坑）→ 改用带 FLAG_ACTIVITY_NEW_TASK + 兜底的安全启动。
7. **语义修正**：v1 seed 把「睡眠·闹钟最大」设为默认兜底，导致白天也套睡眠参数 → v2 新增「日常·常规」作兜底默认，并用 seed_version 升级老数据。

### 环境坑（重要，会反复踩）
- **PowerShell 无法跑 gradlew.bat**：`.bat` 在管道中会报 `Cannot run a document in the middle of a pipeline`；`Start-Process` 又因环境里 `http_proxy`/`HTTP_PROXY` 大小写重复键报 `Item has already been added`。
  → **可用方案**：Git Bash 直接调 Gradle 发行版 sh 脚本：
  `/c/Users/qw_20/.gradle/wrapper/dists/gradle-8.11.1-bin/<hash>/gradle-8.11.1/bin/gradle assembleDebug --no-daemon --console=plain`
  （java 17 已在 PATH，无需 JAVA_HOME；ANDROID_HOME 未设置，SDK 在 `/d/app/play_app/android-sdk`）
- **模拟器进程随 Bash 命令结束被回收**，且 /data 快照不稳定（App 和数据常丢失）。
  → 必须把「启动模拟器 + 等待 boot + 安装 + 验证」写在**同一次 Bash 调用**里。
- 模拟器会周期性弹 "System UI isn't responding"，干扰 uiautomator dump；这是环境问题，不是 App 崩溃（用 logcat 区分）。
- Python 是 Windows 原生程序，读不了 Git Bash 的 `/tmp` 路径，需用项目内相对路径。
