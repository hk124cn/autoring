# 2026-09-10

## 新增「在线升级」功能（自动检测新版本 + 点击升级 + 保留原配置）

### 实现
- 新增 `app/src/main/java/com/example/autoring/update/UpdateManager.kt`：
  - `UpdateConfig`：发布源配置（默认 `hk124cn/autoring`，改 REPO_OWNER/REPO_NAME 即可）
  - `checkForUpdate()`：HttpURLConnection 请求 GitHub Releases API
    `https://api.github.com/repos/{owner}/{repo}/releases/latest`，
    解析 `tag_name`（约定 v1.1.0）+ assets 里的 .apk，语义化版本比较（`isNewer`）
  - `download()`：下载到私有 cacheDir/update/，带进度回调
  - `install()`：FileProvider + ACTION_VIEW 拉起系统安装界面
  - `canInstallPackages()` / `openInstallPermissionSettings()`：Android 8+ 未知应用安装权限
  - `UpdateState` sealed class：Idle/Checking/Downloading(progress)/Ready/Failed
- 零新增依赖：用标准库 HttpURLConnection + org.json（项目原本无网络库）
- `res/xml/file_paths.xml` + Manifest 加 FileProvider（`${applicationId}.fileprovider`）
- Manifest 加 `INTERNET`、`REQUEST_INSTALL_PACKAGES`
- `build.gradle.kts` 的 `buildFeatures` 必须加 `buildConfig = true`
  （**AGP 8.0 起默认不生成 BuildConfig**，否则读 VERSION_NAME 会 Unresolved reference）
- MainViewModel：`checkForUpdate(manual)`（手动忽略节流+给反馈）、`downloadAndInstall()`
  （下载完直接拉起安装）、`canInstallPackages` StateFlow（授权返回后 onResume 自动刷新）
- UI：设置页加「版本与更新」卡片（显示 v1.0.0 + 检查更新按钮 + 进度/失败提示 +
  未授权时给"去授权安装权限"按钮）；检测到新版本弹 AlertDialog（更新说明 +
  "升级为覆盖安装，不会清除你的模式和时间段配置" + 立即升级/稍后）
- 自动检测：冷启动静默检查一次，24 小时内不重复（prefs 记 last_update_check）

### 「升级保留原配置」的原理
覆盖安装（同包名 + 同签名）时系统只替换 APK，/data 下的 Room 数据库与
SharedPreferences 原样保留 → 模式和时间段配置天然不丢。
⚠️ **前提：签名必须一致**。当前是 debug 签名，若以后发 release 签名包，
签名不同会导致覆盖安装失败（必须先卸载 → 数据丢失）。要真正平滑升级，
需先配置正式 keystore，让用户装的基线版本就是正式签名。

### 验证
- 构建 BUILD SUCCESSFUL；设置页出现「版本与更新」卡片 + v1.0.0
- 冷启动自动检查更新时网络不通 → `检查更新异常` 被 catch，**无崩溃**（崩溃计数 0）
- 真实升级流程需用户建好 GitHub 仓库并发布 Release 后在真机验证
